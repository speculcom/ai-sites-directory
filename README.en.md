## Layout

| Path | Content |
|---|---|
| `content/` | **Content source**: one Markdown file per site, with category, description and tags |

| `categories.en.json` / `tags.en.json` / `vendors.en.json` / `descriptions.en.json` | English mappings (category / tag / vendor / description) |
| `check-results.json` | Link-verification snapshot (each entry has a status and a verification date `lv`; `history` records each run's start/done). **The builder and `gen-content.mjs` consume it directly** to render verification status |

| `site/` | Site output (generated by `build-site.mjs`) |

## Three steps after changing content

```bash
node check-links.mjs        # 1 verify (reads nav-data.json, dedupes by domain; writes check-results.json)
node gen-content.mjs        # 2 refresh content/*.md and content-summary.json
node build-site.mjs         # 3 build → output to site/
```

⚠ **`check-results.json` is part of the pipeline, not an optional report**: running
`check-links.mjs` directly changes page output (the verification date and status shown
next to every link).

## Verification criteria (A4.1 state machine · not to be relaxed)

| Status | Criterion | Meaning |
|---|---|---|
| `ok` | 2xx/3xx with no change of registrable domain | Reachable |
| `changed` | 2xx/3xx but redirects to **a different registrable domain** (carries `to`) | Moved; the link still works via redirect |
| `blocked` | 401 / 403 / 429 | Anti-bot, rate limit, or login required — the site is alive |
| `dead` | **404 / 410** | The only criterion that may declare a link dead |
| `unverifiable` | DNS failure / timeout / TLS / 5xx / blocked | **A legitimate terminal state; not declared dead.** Retestable later with `--only=unverifiable` behind a proxy |
| `unknown` | — | Transitional: not yet verified. Only decreases, never increases (`content-freshness.mjs` guards it, baseline 626) |

- Better to miss a judgement than to kill a good link; `unverifiable` is not a debt, it is
  an honest conclusion (DNS failure ≠ dead. Measured: robetta.bakerlab.org fails ENOTFOUND
  locally, opens fine via WebFetch).
- ⚠ Fixed 2026-10-08: on Windows, `curl -o /dev/null` exits 23 (write failure) — the
  response was actually received but treated as "probe failed". 470 of the 626 unknowns were
  this false negative. Now uses `-o NUL`, and rescues the http_code from stdout on non-zero exit.
- Each run appends start/done records to `history`; verification cadence:

```bash
node check-links.mjs                     # incremental: only fills in unknown and untested
node check-links.mjs --limit=100         # in batches (polite default: 150ms per request)
node check-links.mjs --only=unverifiable # retest "probe-restricted" entries behind a proxy
node check-links.mjs --fresh             # full re-verification
```

## Dead links and shutdowns (since 2026-10-08)

Two separate channels — do not mix them:

| Situation | Recorded in | Rendered as |
|---|---|---|
| Probe confirmed 404/410 | `check-results.json` (automatic) | Greyed out + "link dead", **not clickable** (div) |
| Probe failed (unverifiable: DNS/timeout/TLS/blocked) | `check-results.json` (automatic) | **No badge**, link stays clickable (can't probe ≠ dead; badging 400+ entries is just noise — the footer discloses the count once) |
| **Manually confirmed shutdown / acquired and closed** | **`retired: true`** in `nav-data.json` | Greyed out + "shut down", **not clickable** (div) |

`retired` is a **human conclusion** (based on independent external evidence such as "acquired
by X and shut down"), recorded separately from probe results — a DNS failure only means
"could not reach it", not "it is gone". When looking for a successor owner: **you may not
point at the acquirer's domain** (unless that company is itself the successor, e.g. CreateAI).

## Pushing the output

```bash
bash _audit/push-site.sh _data/nav/site speculcom/nav "content update"
```

The `site/` directory contains `index.html` + `brand.*` + `site.css` + `CNAME` + `.nojekyll`
+ `robots.txt` + `sitemap.xml` + `README.md`.

⚠ **`.nojekyll` is required** — without it the Pages build fails (though the old output
stays online, which makes the symptom extremely misleading).
